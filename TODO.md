- [ ] **(Ask)** Build the first durable mirror for PublishedData content, starting with IPFS. **Why this matters:** `201a9f1b` made the event pointer-only, which removed a de-facto full backup (the old event body meant Postgres held a copy of every statement) and left **calldata recovery as the only resolver**. Archive availability is therefore a live, unmitigated risk today, not a solved one — the "EthStorage as mirror #2" framing in [the spike](spikes/ethstorage/README.md) describes a plan whose mirror #1 does not exist yet. The **read half is now built** — `createIpfsContentResolver` in [`sdk/src/subsystems/published-data/ipfs-resolver.ts`](sdk/src/subsystems/published-data/ipfs-resolver.ts), composed after calldata by `createDefaultContentResolver` whenever a gateway is configured, keyed on `publishedDataIdToCid(dataId)` so no extra state is needed. What remains is the **copier**: a process that watches `DataPublished` and pins the bytes, designed so we need not be the one running it. Open design questions to settle first: standalone worker vs. folded into an existing service; whether it pins everything or waits on the policy-list evaluator; and whether we run one initially or ship it for vertical founders to run (interacts with the operator-scoped indexer milestone above).
  - The copier must add with `--cid-version=1 --raw-leaves`. Do **not** reuse `uploadToIPFS` in [`sdk/src/utils/ipfs.ts`](sdk/src/utils/ipfs.ts) — its default `add` flags produce a chunked dag-pb CID that is not `sha256(content)`, silently breaking the identity above.
  - That identity holds only while content fits one block (256KB default chunk). **Establish real document sizes first**; above the threshold both this and EthStorage (blob cap 131,072 bytes, spike check B1) need a manifest with its own content-addressed identity.
  - Obey the two rules in [the PublishedData spec](specs/tech/subsystems/published-data/README.md#two-rules-for-whoever-writes-the-second-backend): the copy is asynchronous and never blocks publication, and the uploader need not be the author (bytes are hash-verified, so a third party can heal a missing mirror). Do not sponsor or relay uploads on the user's behalf.
  - A copier that declines to redistribute some content is a **policy-list consumer** — wire it to the shared evaluator from the policy-list milestone rather than growing a second filtering mechanism.
