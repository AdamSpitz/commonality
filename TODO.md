- [ ] **(Ask)** Make a CauseStarter cause **roster** a published, versioned artifact instead of unversioned `localStorage`, so that a supporter's signature can be distinguished from whatever the founder's page currently shows. Full design, including the rejected alternatives, is [§ The roster is a publication](docs/founder/shaping-your-cause-statements.md#the-roster-is-a-publication); posture context is [ADR 0008](specs/decisions/0008-operated-surfaces-are-lenses.md). Build it in this order, and note that step 1 is worth landing on its own — it fixes the founder-can-silently-swap-planks problem whether or not the badge is ever built:
  1. **Roster document + two identifiers.** Publish all founder-authored display text (summary, title, ordered plank CIDs, mediator blurb — not just summary + CIDs, or the badge is escapable via the title) as a displayable document through `PublishedData`, exactly as `causestarter/src/lib/publishPlank.ts` does for plank text; its CID is the version ID. Point a `MutableRefUpdater` ref `(founderAddress, slug) → CID` at it for the stable ID, which is what goes in the URL — a content hash there would 404 every share on every edit, and since ADR 0008 removed discovery the broadcast link is the only path to a cause. **Do not use `appendToUserList`**: it uploads to IPFS, which is the legacy browser-write path CauseStarter deliberately lacks.
  2. **History display.** `getUserRefHistory` gives "roster changed 3 days ago" and per-plank added-later provenance markers with no new machinery. Add `/cause/<stable>@<version>` for pinned views.
  3. **Coherence attester.** Positive-only, subject = the roster document CID, narrow claim (planks match their own summary, no riders) — *not* merit: a coherent cause we find repellent earns the badge, per ADR 0008. Must be a separate prompt/config from cause-assist's generation path, and treated as *a* trusted attester rather than *the* one.
  4. **Preview-before-publish.** Compute the would-be CID client-side, get a verdict (optionally a pre-signed attestation conditional on that CID), let the founder iterate. **"Publish anyway" must be a peer of "Publish"** — same prominence, no warning dialog, no scolding copy. A preview that is awkward to skip is admission rebuilt in the client, which ADR 0008 exists to prevent. Void the verdict on any edit, following the existing `safety: undefined` pattern in `CauseDetailPage`.
  Main cost to weigh before starting: every roster edit becomes a `PublishedData` publish plus an `updateRef` tx, where editing is currently free and local — check whether the plank publish and ref update can share a transaction. Explicitly **not** in scope: scoping band 2 per-signer to the roster they saw (shelved; the weakest-link pairing already makes the display non-inflatable), and anchors.
